# 練習タイマー

イラストの練習・制作で、作業と休憩を切り替えながら実作業時間を記録するアプリです。タスクをテーマ・サブテーマに分類し、期間別に振り返れます。

このREADMEは、利用者向けの操作説明と、web版ChatGPTなどにJSONの分析・編集や練習案の提案を依頼するための仕様書を兼ねています。**ChatGPTには、このREADMEと最新の `practice-timer.json` を添付して使えます。** 仕様の確認基準は、このリポジトリの `app.js`、`timer-core.js`、`practice-data.js` です（2026-11-14確認）。

## 自分用Macデスクトップ版（beta）

Web版と同じ画面・タイマー計算・JSON形式を使う、Electron製のローカルアプリです。デスクトップ版は試験段階です。スマホでは引き続きWeb版を使えます。データの自動同期はなく、JSONで受け渡します。

### 起動・常駐・ショートカット

- 生成済みの `dist/Practice Timer.app` をダブルクリックして起動します。このフォルダに置いたまま使えます。
- メニューバーに残り時間を表示します。`Ⅱ` は一時停止、`○` は開始前です。クリックすると作業／休憩・選択タスクを確認し、開始・一時停止・再開・セッション終了・画面の再表示ができます。
- ウィンドウの閉じるボタンと `⌘W` は画面を隠します。計測とメニューバー表示は続きます。
- 初期ショートカットは **`⌘⇧Space`：開始・一時停止・再開**、**`⌘⇧Return`：セッション終了**。別アプリの操作中も使えます。ショートカットによるセッション終了には確認画面が出ます。
- Settings → Desktop betaで、入力欄を選んで新しいキーの組み合わせを押すと変更・保存できます。競合するキーはエラーを表示し、直前の設定を保ちます。設定欄でキーを記録している間はタイマー操作を止めます。
- メニューバーの「Quit Practice Timer」または `⌘Q` でアプリを終了します。終了時は計測を一時停止して保存し、次回は一時停止状態で復元します。Macのスリープ時も一時停止します。Macログイン時の自動起動は設定していません。

### 保存とWeb版からの移行

- タスク・設定・実績・計測途中の状態は、このMacのアプリ用データ領域へ自動保存します。通常は `~/Library/Application Support/Practice Timer/practice-timer.json`。ショートカットとバックアップ先は同じ場所の `desktop-settings.json` に保存します。
- アプリ本体とは別に保存するため、同じアプリ名・データ保存先を維持して更新すれば記録を引き継ぎます。内部ファイルを直接編集する場合は、先にアプリを終了し、JSONを書き出してください。
- Web版のデータは自動で移しません。Web版でタイマーを終了 → Settings → Backup → Save now → デスクトップ版のImport、の順に移します。Importは全データの置き換えです。既にデータがある場合は先にJSONを保存してください。
- デスクトップ版でもBackupから複数のJSON保存先を登録できます。自動保存の間隔はWeb版と同じく、最終変更から2分、変更が続く場合は最大5分。外部変更を検出した保存先は上書きを止めます。
- 保存先未登録の「Save now」やメニューバーの「Export JSON…」では、保存ダイアログでJSONを書き出せます。スマホで見る場合はそのJSONをWeb版へImportします。クラウド同期そのものはアプリでは行いません。
- 保存済みデータが読めない場合はファイルを保持し、上書きを止めます。有効なJSONのImportで復旧できます。保存エラーの際は画面上部に表示し、正常に保存できるまで通常の終了を止めます。

### 開発・更新

Node.jsを導入したMacで、初回はこのフォルダで `npm ci` を実行します。開発中の起動は `npm start`、アプリ生成は `npm run build` です。最初の起動・生成時はElectron本体をダウンロードする場合があります。生成したアプリはこのMac用で、現在はローカル利用向けです。署名付き配布・自動更新は含みません。

更新は、アプリを終了 → 修正とテスト → `npm run build` → 同じ `dist/Practice Timer.app` を起動、の順です。実行中のアプリを検出した場合、生成処理は置き換えを中止します。GitHubへの送信や公開は不要です。

- `npm test`：既存Web機能と、デスクトップ版のファイル保存・配信テスト。
- `npm run test:desktop`：一時データだけを使い、実際のElectronで非表示計測・メニューバー・設定・バックアップ・復元・Web版を確認。
- `npm run test:release`：`npm run build`で生成したアプリの安全設定、保存・復元、改ざんしたアプリの起動拒否を確認。製品版はメイン処理のデバッグ機能を無効にしているため、`test:desktop`は開発用Electron、`test:release`は生成したアプリをそれぞれ検証します。
- アプリ内の画面は外部へ公開せず、`127.0.0.1`だけのローカルHTTPで配信します。アプリ終了時に配信も停止します。アプリ用データ・デスクトップ用ソースは配信対象外です。
- `desktop/`と`package.json`・`package-lock.json`はGit管理対象です。`node_modules/`、`dist/`、テストデータ、実際のバックアップJSONは送信対象から除外します。

## ChatGPTに渡すときの使い方

1. アプリのタイマーを終了し、Settings → Backup → Save nowで最新のJSONを保存します。一時停止中も計測途中なので、JSONを編集して戻す場合は終了してから保存してください。
2. このREADMEと、そのJSONをChatGPTへ添付し、分析・提案・JSON編集のどれを頼みたいか伝えます。案出しだけならREADMEと目的だけでも使えます。
3. 編集したJSONを戻す前に、変更内容を確認し、編集前のバックアップを手元に残します。
4. Settings → Backup → Importで読み込みます。**読み込みはテーマ・タスク・過去記録・設定など全データの置き換えです。追加読み込み・自動マージではありません。**

自動バックアップの保存先と同じファイルをChatGPTの出力で先に上書きすると、アプリ側の外部変更検出でその保存先への自動保存が止まる場合があります。編集前のバックアップを保持し、生成結果はまずImportから読み込んでください。

依頼文の例：

```text
添付のREADMEを練習タイマーの仕様として参照し、添付JSONを現在のデータとして扱ってください。
目的：〔例：手の描写と光の理解を重点的に練習したい〕
使える時間：〔例：平日1日30分、週末1時間〕
依頼：既存のテーマとタスクを確認し、次の1週間に取り組む案を優先順で提案してください。
案ごとにテーマ／サブテーマ、タスク名、最初の一歩を含むメモ、完了の目安を示してください。
記録の時間だけで習熟度を断定せず、記録から分かることと提案上の仮説を分けてください。
```

JSONの編集まで頼む場合は、次のように追記します。

```text
提案した内容を追加した、アプリへImportできる完全な practice-timer.json を作成してください。
元のID、既存タスクの相対的な順序、過去記録、累計時間、Routine、音、1日の区切りを保ち、
依頼したテーマ・サブテーマ・未完了タスクだけを追加してください。
既存の分類を再利用できる場合はそのIDを使い、新しい項目だけ重複しないIDを発行してください。
過去の実績は作らず、変更点の説明とJSONファイルを分けてください。
計測途中のrunがある場合は編集せず、タイマー終了後の最新JSONが必要だと伝えてください。
```

## アプリの概念と、提案するときの考え方

| 概念 | 役割・使い分け |
| --- | --- |
| Theme（テーマ） | 継続して時間を比較したい練習分野・制作領域。例：人体、光と色、背景、作品制作。JSONでは `groups`。 |
| Subtheme（サブテーマ） | テーマ内の内訳。例：人体 → 手、光と色 → 逆光。階層はテーマとサブテーマの2段だけ。 |
| Task（タスク） | 実際に着手する行動。例：「手の写真を見て、指の付け根を意識したスケッチを5枚描く」。 |
| Memo（タスクのメモ） | 手順、最初の一歩、観察点、完了の目安などを書く自由欄。JSON名は `firstStep` だが、最初の一歩だけに用途を限定しない。 |
| Routine（手順） | 全タスクで共通の作業・休憩の時間配列。タスクごとの所要時間・締め切りではない。 |
| Session（保存済み記録） | 休憩・一時停止を含まない実作業区間。同じタイマー起動から複数件の記録ができる。 |
| Run（計測途中） | 開始から終了までの、まだ保存済み記録になっていない計測状態。 |

- タスクの分類先は、テーマ1つ、サブテーマ1つ、未設定のいずれかです。サブテーマを選ぶと親テーマの合計にも含まれます。複数のテーマ・タグは付けられません。
- テーマへ直接割り当てた時間は「No subtheme」、分類なしは「Unassigned」として表示します。「未設定」用のテーマを新規作成する必要はありません。
- タスクは何回でも計測できます。タイマーの終了とタスクの完了チェックは別操作で、時間を記録しても自動で完了しません。
- 同じ計測の途中でタスクを次々に切り替える機能はありません。未選択で開始した場合は後から1つ選べます。その回の作業は終了時点の選択タスク・名前・分類で記録されます。
- タスク名や分類の変更は、保存済みの過去記録には遡って反映しません。過去記録の修正はReviewの記録編集、または明示的なJSON編集で行います。
- テーマ・サブテーマの削除では該当するタスクと過去記録の分類が未設定になります。タスク・記録・時間は残ります。タスクの削除でも過去記録は残ります。

提案では、まず既存の分類を使い、継続的に比較したい分野だけテーマ／サブテーマを増やします。一度だけ行う行動はタスクにします。タスク名は行動が分かる表現にし、メモに「何から始めるか」「どこを観察するか」「どこまで行えば一区切りか」を短く含めると着手しやすくなります。日本語の名前・メモもそのまま使えます。

保存されるのは主に時間・タスクの完了状態です。作品画像、出来栄え、理解度、練習回数・枚数、締め切り、優先度、目標時間、振り返りメモの専用項目はありません。枚数などをメモへ書いても、達成数を自動集計する機能はありません。記録が少ない分野を苦手と断定したり、記録が多い分野を習得済みと断定したりせず、目的・制作課題・使える時間を踏まえて提案してください。

## JSON仕様：全体

JSONはUTF-8の標準JSONです。コメント、末尾カンマ、省略記号、`NaN`、`Infinity` は使いません。Importのファイルサイズ上限は **5,000,000バイト** です。

| キー | 型・意味 |
| --- | --- |
| `format` | 固定文字列 `"practice-timer-beta"`。正式版でも互換性のためこの識別名を使う。`"practice-timer"` へ変えない。 |
| `version` | 数値 `1`。READMEの更新日やアプリの公開回数とは無関係。 |
| `steps` | Routineの配列。未設定なら `[]`。 |
| `groups` | テーマの配列。各テーマに `children` 配列を持つ。 |
| `tasks` | タスクの配列。未完了タスクの表示順はこの配列内の順序。完了済みの表示は完了日時の新しい順。 |
| `sessions` | 保存済みの作業区間の配列。計測途中の時間は含まない。 |
| `totalWorkMs` | 累計実作業時間、ミリ秒。計測途中ならその作業時間も含む。 |
| `run` | 計測なしなら `null`。計測途中なら後述のオブジェクト。 |
| `selectedTaskId` | 選択中のタスクID、または `null`。新規データは `null` を推奨。存在しないIDや、計測途中ではないときの完了済みタスクIDは、読み込み時に `null` になる。 |
| `sound` | `volume` と `pitch` を持つ通知音設定。 |
| `dayStartMinutes` | 1日の区切り。午前0時からの分数、整数 `0`〜`1439`。初期値 `300`（5:00）。 |

`format`、`version`、`steps`、`groups`、`tasks`、`sessions`、`totalWorkMs` は必須です。読み込み時、`run` と `selectedTaskId` の省略は計測・選択なし、`sound` の省略／`null` は `{"volume":100,"pitch":0}`、`dayStartMinutes` の省略は `300` として扱います。新しく生成するJSONには全キーを明示してください。未知の独自キーは読み込み後の保存で保持されないため、専用項目を勝手に増やさないでください。

### ID・日時・単位の共通ルール

- `groups[].id`、`children[].id`、`tasks[].id`、`sessions[].id` は空でない文字列で、**これら全種類を通じて重複不可**です。UUIDなどを使えます。新しいIDは既存のIDと照合してください。
- `recordGroupId` は同じタイマー起動の記録をまとめる文字列で、複数記録で共有します。上記の一意IDとは用途が違い、単独記録ではその記録の `id` と同じ値にもできます。
- `targetId` はテーマまたはサブテーマのIDを1つ指定するか `null`。サブテーマのときも親IDを別項目に書く必要はありません。存在しないIDや空文字列は不可です。
- 日時はUnix時刻の**ミリ秒**（UTC基準、1970-01-01からの経過時間）です。ISO日時の文字列や秒単位の数値を入れません。日時の変換時はタイムゾーンを明示してください。JSON自体にはタイムゾーン設定はありません。
- `workMs`、`totalWorkMs`、`remainingMs` などの時間量もミリ秒。1分 = `60000`、1時間 = `3600000`。Routineの `steps[].minutes` は分、`dayStartMinutes` は午前0時からの分数です。

### Routine：`steps`

各要素は `{"type":"work","minutes":25}` の形です。

- `type` は `"work"` または `"rest"`。画面のBreakに対応するJSON値は `"rest"` です。
- `minutes` は数値で `0.1`〜`240`、0.1分刻みです。
- 空配列や片方の種類だけでも保存・Importはできますが、開始にはWorkとBreakが最低1つずつ必要です。
- 開始後は配列を上から順に実行し、最後まで進むと「最後に設定したWork」と「最後に設定したBreak」を交互に繰り返します。配列全体を最初から繰り返す方式ではありません。
- 計測中のRoutine変更は次の計測に適用されます。進行中の手順は `run.steps` に保持します。

### テーマ：`groups`

テーマは `{"id":"theme-anatomy","title":"人体","children":[]}`、サブテーマは `{"id":"subtheme-hands","title":"手"}` の形です。

- テーマ・サブテーマの `title` は空白だけではない文字列で、それぞれ最大60文字です。
- 子がなくてもテーマに `children: []` を明示します。サブテーマにさらに `children` は作りません。
- テーマ名・サブテーマ名が同じでもIDが違えば別項目です。集計・参照は名前ではなくIDで行います。
- 時間の合計は記録から算出します。テーマに `totalMs` などの集計値を書き足す必要はありません。

### タスク：`tasks`

| キー | 型・制約 |
| --- | --- |
| `id` | 共通ルールに従う一意ID。 |
| `title` | 空白だけではない文字列、最大100文字。 |
| `firstStep` | メモの文字列、最大500文字。不要なら空文字列 `""`。改行可能。省略不可。 |
| `targetId` | テーマID、サブテーマID、または `null`。 |
| `completedAt` | 未完了は `null`。完了済みは0以上の有限なUnixミリ秒。真偽値ではない。 |

文字数制限は実装のJavaScript文字列長で判定します。絵文字などは見た目の1文字が2文字以上として数えられる場合があるため、上限には余裕を持たせてください。新規提案のタスクは `completedAt: null` とし、完了実績を作りません。追加タスクを先頭へ並べる場合も、既存タスク同士の順序は維持してください。

### 保存済み記録：`sessions`

| キー | 型・制約 |
| --- | --- |
| `id` | 共通ルールに従う一意ID。 |
| `recordGroupId` | 同じタイマー起動分をまとめる空でない文字列。省略時はその記録の `id` が使われる。 |
| `startedAt` | 開始のUnixミリ秒。開始不明の旧記録は `null`。 |
| `endedAt` | 終了のUnixミリ秒。0以上の有限な数値。 |
| `workMs` | 実作業時間。0以上の有限な数値。開始時刻がある場合は `endedAt - startedAt` と一致（読み込み許容誤差1ms）。 |
| `taskId` | 記録時のタスクID、または `null`。タスク削除後も元のIDを保持できる。 |
| `taskTitle` | 記録時のタスク名の文字列、または `null`。現在のタスク名と違うことがある。 |
| `targetId` | 記録に付いた分類先ID、または `null`。現在のタスクの分類からは独立。 |

開始時刻がある記録は `0 <= startedAt < endedAt` とします。休憩・一時停止で区切られるため、1回のタイマー起動が1件の記録とは限りません。`recordGroupId` が同じ記録の `workMs` を合計すると、その起動分の保存済み作業時間になります。グループ内の最初の開始から最後の終了までを引いた時間には休憩・一時停止が含まれ得るため、実作業時間として使いません。

`taskId` は削除済みタスクを参照していても読み込めますが、`targetId` は現存するテーマ／サブテーマのIDでなければ読み込めません。過去記録を分析するときは各記録の `taskTitle` と `targetId` を使ってください。現在のタスクから一律に付け直すと過去の分類を変えてしまいます。

### 累計と計測途中：`totalWorkMs`・`run`

通常、`totalWorkMs = sessions内のworkMs合計 + (runがあればrun.sessionWorkMs)` です。テーマ・タスクを追加するだけなら、元の `totalWorkMs` を変更しません。読み込みは合計より1msを超えて小さい累計を拒否しますが、大きい値は受け付ける場合があります。差があっても実績を推測して補ったり、累計を無断で修正したりせず、その差を報告してください。

**新規作成は `run: null`。既存JSONの `run` がオブジェクトなら、原則としてアプリで終了して再保存したJSONを使って編集します。** `run` を単に `null` にすると、計測途中の記録を失うおそれがあります。読んで分析するだけなら、`sessions` の保存済み時間と計測途中の時間を分けて扱ってください。

計測途中のJSONを理解するためのフィールド一覧：

| キー | 意味 |
| --- | --- |
| `steps` | その回のRoutine。Work・Breakの両方が必要。 |
| `row`・`phase` | 現在の手順の0始まりの添字と種類。`steps[row].type` と `phase` は一致する。 |
| `looping` | 最後のWork／Breakを交互に繰り返す段階かどうか。真偽値。 |
| `remainingMs` | 現在の工程の残り時間。0より大きく、当該工程の設定時間以下。 |
| `status`・`lastTick` | バックアップでは `"paused"` と `null`。読み込み後は一時停止状態で復元する。 |
| `totalWorkMs` | 計測途中分を含む累計。最上位の `totalWorkMs` と一致（許容誤差1ms）。 |
| `sessionWorkMs` | この回で計測済みの実作業時間。まだ `sessions` に入っていない。 |
| `workIntervals` | この回の作業区間の配列。各要素は `startedAt`・`endedAt` を持つ。休憩・一時停止を含まない。 |
| `legacyWorkMs` | 開始時刻のない旧形式から引き継いだ、この回の作業時間。通常は `0`。 |
| `newWorkInterval` | 次の作業加算時に新しい区間を作る内部フラグ。 |
| `recordGroupId` | 終了時に作成する各記録へ付けるグループID。 |

`workIntervals` の各区間は有限な数値で `startedAt < endedAt`。区間の長さの合計と `legacyWorkMs` を足した値が `sessionWorkMs` に一致します（許容誤差1ms）。`workIntervals` がない旧形式は全 `sessionWorkMs` を開始不明の時間として復元するため、既存フィールドを削らないでください。

### 音：`sound`

- `volume` は整数 `0`〜`500`。**画面の音量0〜100%とは尺度が違い、JSON値 = 画面の% × 5** です。画面20%は `100`、画面100%は `500`、消音は `0`。初期値は `100`。
- `pitch` は整数 `-12`〜`12`、半音単位。初期値は `0`。

## JSONを分析するときの集計ルール

- 集計のタイムゾーンはアプリを使う端末のローカル時刻です。ChatGPT側で分析するときは利用者の指定を使い、不明ならタイムゾーンを確認するか、仮定を明記します。
- 1日は `dayStartMinutes` の時刻から翌日の同時刻まで。初期値300なら「11月14日」は11月14日5:00以上、11月15日5:00未満です。週は月曜始まり。月・年も初日の設定時刻で区切ります。
- 開始時刻がある記録は、対象期間との重なりを切り出して集計します。終了日へ全時間を寄せたり、日またぎの全時間を両日に加算したりしません。範囲は開始を含み終了を含まない `[start, end)` です。
- `startedAt: null` の記録は、終了時刻が属する集計期間に `workMs` 全体を計上します。日別合計・週月年・テーマ集計には含めますが、時刻を特定できないため日の時間帯別グラフには含めません。
- テーマ合計は、テーマへ直接付いた記録と配下のサブテーマの記録の合計です。親合計と子合計を再度足すと二重計上になります。未設定は別に集計します。
- ReviewとThemesの集計対象は保存済みの `sessions` です。計測途中の `run.sessionWorkMs` は累計表示に含まれますが、期間別グラフ・テーマ集計の保存済み記録にはまだ含まれません。
- 時間表示は `2h 05m` のように秒を切り捨てます。JSONの精度は保たれています。表示値同士の足し算が合わなくても、丸め前のミリ秒で確認してください。
- 記録件数は練習回数やタスク完了数とは一致しません。完了数を数える場合は `tasks[].completedAt` を使い、削除済みタスクの完了状況は復元できないことを踏まえます。

## ChatGPTがJSONを編集・生成するときの確認事項

1. 分析・案出しだけならデータを変更しません。JSON編集を依頼された場合も、依頼の範囲外の記録・設定を変更しません。
2. 現在のデータを残して追加するには、最新の完全なバックアップが必要です。元データがない場合は提案内容を文章や表で示し、既存データを空にした「追加用JSON」を作りません。新規データとして作る場合は全置換用だと明記します。
3. 既存のIDを維持し、新しい項目にだけ一意IDを発行します。テーマを追加したら、そのIDをタスクの `targetId` から正しく参照します。新規サブテーマは親テーマの `children` 内に置きます。
4. 過去記録、完了日時、累計時間を推測で作りません。テーマ・タスクの提案に、架空の学習実績や予定時間を `sessions` として混ぜません。
5. `run` があるJSONは、終了後の最新バックアップを用意してから編集します。計測途中の時間を無断で削除したり、保存済み記録へ重複して移したりしません。
6. 完全なJSONの構文、必須キー、文字数、IDの重複と参照先、日時と時間量の単位、記録区間の長さ、累計の整合、ファイルサイズを確認します。変更前後のテーマ・タスク・記録件数と累計時間を比較すると確認しやすくなります。
7. 出力ファイル名は `practice-timer.json` とし、JSON本体へ解説を混ぜません。アプリで読み込み確認をしていない場合は、その点を明記します。

JSONにはタスク名・メモ・作業日時が含まれます。画像、バックアップ保存先の登録情報、ブラウザの通知許可はJSONに含まれません。

`index.html` を直接開いて使います。起動時はタイマー画面です。下部の「Timer・Tasks・Review・Themes・Settings」で画面を切り替えます。画面内の操作・案内・エラーは英語で表示します。タスク名・テーマ名・メモなど、自分で入力した内容はそのまま保持します。最初は手順が空なので、「Settings」→「+ Add」で作業と休憩の時間を設定してください。追加時は直前と交互になる種類と、その種類の直近の時間（未設定ならWork 25分・Break 5分）を入れます。Routineはつまみ・種類・分数・削除を横1行にまとめ、つまみのドラッグで並べ替えられます。つまみにフォーカスして上下キーでも移動でき、Escapeやドラッグの中断で取り消せます。追加・削除・並べ替え・種類・時間の変更は自動保存します。入力途中の空欄や範囲外の値は適用せず、最後の有効な内容を保ちます。WorkとBreakが両方揃うまでは開始できません。401〜479pxでは設定の2列を保つため、種類と分数を上下に並べます。最後に設定した作業時間と休憩時間を交互に繰り返します。設定の編集中に別のタブへ移動しても入力を保持します。計測中の変更は次の計測から反映し、進行中の時間や工程は変えません。

タスク画面では、タイトルだけで素早く追加できます。新しいタスクは一覧の先頭へ追加します。画面下の入力欄は「Add task」と表示し、追加バーはスクロール中も下部ナビゲーションの上に残ります。完了済みタスクの末尾や取り消し通知が追加バーに重ならないよう、入力欄の折り返しに合わせて余白を調整します。未完了の見出しと件数は省いています。入力欄が空の状態（空白だけの場合も含む）で「+ Add」を押すと詳細入力が開き、「タイトル」「メモ」「テーマ」「サブテーマ」を設定できます。タイトルを入力済みなら「+ Add」ですぐに追加します。テーマは練習の分野や題材、サブテーマはその中の項目です（例：テーマ「人体」→サブテーマ「手」）。サブテーマを選ばなければテーマへ直接加算し、「サブテーマなし」と表示します。テーマ自体を選ばなければ「未設定」になります。一覧はチェックとタイトルを中心に表示し、タイトルを押すと直接「Edit task」を開きます。展開三角や「Use this task」は置かず、計測するタスクの選択はタイマー画面で行います。編集画面には「Save changes」「Cancel」「Delete」を横に並べ、Deleteは確認後にタスクだけを削除して過去の記録を残します。計測中の選択タスクは削除できません。チェックで完了済みへ移し、右下に約5秒表示する「Undo completion」ボタンまたは完了済みのチェック解除で復帰できます。連続して完了にした場合は最後の1件を取り消せます。完了・取り消しではスクロール位置を保ちます（一覧が短くなって画面の下端に達した場合は、表示可能な位置まで調整されます）。過去の計測記録は残ります。

タイマーは作業を鉛筆、休憩をカップで表示します。円の青い部分は現在の工程の残り時間を表し、12時の位置から時計回りに減ります。作業中の数字はブラウン、休憩中はブルーです。円の下の棒グラフアイコンはLogged（この回の作業時間）で、休憩と一時停止を含めず、終了時に記録へ保存して表示を0に戻します。一時停止中は小さな一時停止マークを添えます。主ボタンは再生マーク（開始・再開）と一時停止マークが同じ位置で切り替わり、左のスキップマークで次の工程へ進み、右の四角で終了して記録します。マウスを重ねると説明を確認でき、読み上げ用の操作名も付いています。手順がなければ主ボタンの歯車から設定へ進めます。開始前の時計には最初の設定時間を表示します。タイマーの終了とタスクの完了は別の操作です。

タイマー画面では幅401px以上で左1/3に未完了タスク、右2/3にタイマーを並べます。幅400px以下ではタイマーの下にタスク一覧と追加欄を置きます。「Practice tasks」の見出しと丸い選択マークは省き、タスクのタイトルを広く表示します。選択状態は背景色と文字の太さで示します。一覧に入りきらないタスクはスクロールし、長いタイトルは「…」で省略します。入力欄と「＋」から追加すると、そのタスクを選択します。追加したタスクは一覧の先頭に置きます。

タスクを選択して計測を始めると一覧を隠してタイマーを画面中央へ置きます。一時停止中も中央のままにし、終了すると左右配置へ戻します。左側のインライン編集欄はありません。上部のタスクタイトルを押すと編集ポップアップを開き、タイトル・メモ・テーマ・サブテーマを保存できます。変更はこの回の記録にも反映します。タイトルにマウスを重ねても下線は表示しません。未選択で計測を始めた場合はタイマー画面の一覧を残して後から選べるようにし、選択した時点で一覧を隠して中央表示にします。タイマー終了時の「Logged …」という文字行は省き、棒グラフアイコン横の作業時間は残します。

未完了タスクは、行の右端のつまみをドラッグして並べ替えられます。マウスとタッチに対応し、つまみにフォーカスして上下キーでも移動できます。タイマー画面では一覧の上下端で自動スクロールします。順序はタスク画面とタイマー画面で共通で、再読み込みやJSONバックアップにも引き継ぎます。完了済みは従来どおり完了日時の新しい順です。

通常の開始・再開・工程移行の説明は表示せず、アイコンと時間で状態を示します。保存・音・通知の失敗や長時間の中断は表示します。PCでは列の並びを保ち、タイマー円はタスク名・メモ・操作部を除いた残りの高さに収めます。計測前後で円の最大寸法は変えません。極端に小さな窓や長い内容で高さが足りないときはスクロールします。タイトルは設定画面にまとめています。タスク・振り返り・テーマ画面は、下部ナビゲーションと重複する最上部の見出しを省いています。

設定の「通知音」で、作業・休憩に共通の音量（0〜100%、0は消音）と音の高さ（標準から上下12半音＝1オクターブ）を調整できます。新しい100%は前版の500%相当で、1目盛りが前版の5%分です。前版の300%は60%、従来の標準100%は20%と表示し、保存済みの音の大きさはそのまま引き継ぎます。音の設定は変更時に自動保存され、次に鳴る音から反映します。「作業」「休憩」の再生ボタンで試聴できます。作業音は約0.48秒、休憩音は3音を約1.3倍速で鳴らす約0.58秒です。設定はJSONバックアップにも含め、音の設定がない旧バックアップは従来と同じ大きさ（新表示20%）で読み込みます。

ReviewではDay・Week・Month・Year・Allをつながった期間バーで切り替えます。All以外は前後の期間を見られます。幅401px以上では左に合計、右にグラフを置き、400px以下では合計の下にグラフを置きます。日付切り替えの文字は16px、前後ボタンの操作範囲は44pxを保ちながら上下の余白を詰めています。小窓ではグラフの高さと余白を減らし、Monthの2桁の日付が横にはみ出さないようグラフ左右の余白は保ちます。期間バーの文字は15px、操作範囲の高さは44px以上を保ちます。選択期間の合計を大きく、その下に全期間の累計を小さく表示します。作業時間の表示はテーマ・グラフ・記録保存時も含めてすべて `0h 25m`、`2h 05m`、`125h 30m` の形式です。秒は切り捨てて表示し、1分未満は`0h 00m`になりますが、記録自体の秒以下の精度は保持します。各項目と合計はそれぞれ集計してから切り捨てるため、表示上の足し算が一致しない場合があります。タイマーの残り時間には秒を表示します。

設定の「振り返り」→「1日の区切り」で日付を切り替える時刻を設定できます。初期値は朝5:00で、たとえば11月12日は11月12日5:00から翌13日5:00の直前までです。週は月曜始まりで月曜5:00〜翌月曜5:00、月・年もそれぞれ初日の設定時刻で区切ります。変更は自動保存し、過去の記録も新しい区切りで再集計します。記録の日時や総作業時間は変更しません。設定はJSONにも保存し、この設定を含まない従来のデータは5:00として読み込みます。

Day・Week・Month・Year・Allは、同じ縦棒グラフで作業時間を表示します。Allは最初の記録から最後の記録まで年別に比較し、空の年も表示します。年の棒からYear、月の棒からMonth、日の棒からDayへ移れます。年の境界にも「Day starts」の設定を使い、年をまたぐ区間を重複させません。日には区切りの時刻から1時間ずつ24本（5:00設定なら5時台〜翌4時台）、週・月には1日ずつ、年には1か月ずつの合計を表示します。時刻・日付・月の横軸と、作業時間の縦軸を共通の配置にし、混み合う日・月の横軸ラベルは間引きます。棒にマウスを重ねると各区間の時間を確認できます。週・月の棒を押すとその日、年の棒を押すとその月に移ります。日の縦軸上限は通常1時間で、週・月・年は作業量に合わせて変わります。端末のローカル時刻で集計し、夏時間の切替日などは実際の1日の長さに合わせて時間帯の本数が変わる場合があります。

ThemesもDay・Week・Month・Year・Allの期間バーを使い、初期表示はAllです。幅401px以上は2列、400px以下は1列のカードでテーマを表示します。テーマ名と時間はタスク名と同じ16pxの太字にそろえ、カードの上下の余白を詰めています。すべてのテーマとUnassignedを0時間でも表示し、共通の時間目盛りの横棒と数値で比較できます。時間は他の画面と共通の `100h 00m`、`2h 30m` の形式です。テーマの追加欄は従来どおり下部ナビゲーションの上に固定しています。

テーマカードを押すと詳細ポップアップを開きます。サブテーマの追加と比較、名前横の鉛筆からの名前変更・削除はこの中で行います。サブテーマの目盛りはそのテーマ内で共通とし、最長時間に薄い縦の目安線を置きます。0時間のサブテーマも表示し、全項目が0時間の場合は目安線を省きます。「No subtheme」は目安の計算に含めず別掲します。サブテーマの時間はテーマの合計に含まれます。テーマやサブテーマを削除してもタスク・記録・時間は残し、該当する割り当てを未設定に戻します。Unassignedカードのポップアップでは、テーマがない記録の時間をタスク名ごとにまとめます。

Dayの「Sessions」は時刻・鉛筆アイコン・タスク名・作業時間を1行に並べます。鉛筆は時刻とタスク名の間に配置し、テーマは表示しません。縮小時もこの並びを保ちます。長いタイトルは「…」で省略し、マウスを重ねると全文を確認できます。同じ集計日内の年月日は省き、集計日の外にまたがる区間では外側の日付を添えます。「この日」が付いた作業時間は、区間全体のうち選択した集計日内の時間です。行の鉛筆アイコンから日時、タスク、テーマ・サブテーマを直し、1件だけまたは同じタイマー起動分をまとめて削除できます。休憩と一時停止中は作業時間に入りません。

旧形式の記録には開始時刻がないため、「開始時刻なし」と表示し、終了時刻が属する集計日に合計します。時間帯を特定できないため日の24時間グラフには含めず、グラフの下に別掲します。日の合計・テーマタブの集計・週月年のグラフには含まれます。必要ならその記録の日時と作業時間を修正できます。振り返りメモはアプリには保存しません。

Settingsは幅401px以上で左にRoutine・Day starts、右にNotifications・Sound・Backupの2列構成です。400px以下ではRoutineからBackupまで1列に並べます。音量・高さの下にWork／Breakの試聴ボタンを置き、小窓では縦に並べて操作範囲を保ちます。NotificationsのOn／Off／Blocked／Unavailableは実際のブラウザ許可を示し、画面を開いたときやウィンドウに戻ったときに更新します。OSの通知抑制や集中モードの状態を示すものではありません。

Settingsから、画像を含まないJSONを保存・読み込みできます。読み込みは現在のデータを置き換え、計測中は実行できません。通知の確認には、ブラウザが通知を許可できる環境が必要です。

Backupの「Add destination」で、`practice-timer.json` の保存先を設定できます。iCloud Driveなど、端末から選べる場所へ名前を付けて複数登録できます。登録すると現在のタスク・時間・テーマ・各設定をすぐに書き出し、その後は変更が止まって2分後、計測中など変更が続く場合は5分ごとに自動保存します。保存先はこのブラウザに記憶し、再起動時にも引き継ぎます。保存先の登録自体はJSONには含めません。ファイル名は各保存先とも `practice-timer.json` で固定です。

保存先ごとに更新待ち・最終保存時刻・アクセス再許可・保存エラーを表示します。「Save now」で全保存先へ待たずに書き出せます。保存先がない場合や直接保存に非対応のブラウザでは、同じボタンからJSONをダウンロードします。別のダウンロードボタンは置いていません。「Import」でJSONを読み込みます。自動保存は常時オンで、旧版でオフにしていた設定もオンへ移行します。保存先の「•••」メニューには個別のSave／Change／Removeと、保存日時やエラーの詳細があります。Changeでファイルを選び直し、Removeで登録を外せます。解除してもファイルは削除しません。アクセス権が切れた場合は「保存」を押して再許可してください。別の操作でファイルが更新された場合は、その保存先への自動保存を止めます。ファイルの内容を確認し、「保存」から上書きするか、必要なJSONを読み込んで復元してください。JSONの読み込みが自動で行われることはありません。

自動保存はアプリを開いている間に動作します。計測途中の作業時間も含み、JSONを読み込んだときは一時停止状態で復元します。閉じる直前の変更までJSONへ残したい場合は「Save now」を押し、保存済みになったことを確認してください。ブラウザ内への保存は従来どおり継続します。ファイルへの保存済み表示は端末上での書き込みを表し、クラウドへの同期完了はFinderや保存先のサービスで確認してください。

自動保存はファイルへの直接保存に対応するブラウザ（Chrome・Edgeなど）で利用できます。非対応の場合も「Save now」によるダウンロードと「Import」は使えます。保存先を記憶できない場合は画面に表示し、次回は再設定が必要になる場合があります。ブラウザの保存データを読めないときは、空の内容でバックアップを上書きしないよう、保存先への書き出しを停止します。

設定と累計作業時間はブラウザのローカルストレージに保存されます。作業途中でページを閉じた場合、再度開くと一時停止状態から再開できます。アプリを完全に終了した状態やPCのスリープ中には、音・通知は保証されません。
